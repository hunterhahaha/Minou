# NiCode UI 改造路线图

> 建立日期：2026-10-27。设计依据：[design-system.md](design-system.md)。
> 文档基线已建立；UI-01～UI-06 已完成，UI-07～UI-19 未开始。已有 UI 功能不等于本方案的规范化工作已完成。

## 1. 独立会话如何使用

1. 阅读根目录 AGENTS.md、design-system.md 和本文，再核对 [架构与执行流程](architecture.md)、当前代码、[开发与验证指南](development.md) 与已有差异；仅文档任务遵循 AGENTS.md 验证豁免。
2. 根据用户当前请求选择一个任务。本文不是一次完成全部任务的授权，也不允许附带实现参考仓库的新功能。
3. 核对前置任务；若相关目标已由当前代码满足，先用差异与验证证据确认，再更新状态，不盲目重复修改。
4. 修改前说明目标、文件职责、数据流、关键边界和验证范围；编辑代码符号前执行 GitNexus impact。UNKNOWN 必须补查，HIGH/CRITICAL 必须先提示。
5. 只完成一个明确区域；预计跨越大量模块时先拆分。保留当前已有改动，不重置、全局格式化或顺手重构。
6. 交付后更新当前任务的状态和验证记录；没有证据不能勾选完成，未执行的检查不能写成通过。

完成状态：`未开始`、`进行中`、`待验证`、`已完成`。因外部条件无法继续时记录原因和所需条件，不把未完成标成已完成。

统一保护要求：只改视觉和必要展示标记。后端、IPC、事件处理、业务状态、持久化、路由身份、发送/队列/审批/模型保存及焦点/滚动行为不得因 UI 改造改变。完整红线见 design-system.md 第 1 节。

## 2. 阶段与建议顺序

| 阶段 | 任务 | 实施方式 |
| --- | --- | --- |
| 基础规范 | UI-01～UI-04 | 先 Token 与角色，再更新组件使用；不将全部选择器一次重写 |
| 输入与导航 | UI-05～UI-07 | Composer、模型菜单和侧栏分别交付 |
| 对话内容 | UI-08～UI-11 | 消息、Markdown、审批、队列分别交付 |
| 设置与浮层 | UI-12～UI-16 | 设置外壳及三个分区分别推进，搜索和创建单独核对 |
| 响应式与复核 | UI-17～UI-19 | 局部容器适配后整体回归；每个早期任务仍需自身基本验证 |

优先建议：从 UI-01 开始，再按依赖完成 UI-02～UI-06，先让基础值与两个输入入口一致。其余任务按明确需求选择，不自动扩大范围。

### UI-04 统一按钮层级与焦点反馈
