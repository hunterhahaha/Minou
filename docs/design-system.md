# NiCode 前端设计规范

> 记录日期：2026-10-27。来源：本次 open-claude-ui 学习与 NiCode 前端分析。
> 本文是后续前端优化的设计基线，不表示规范已全部落地。实施状态只在 [UI 改造路线图](ui-roadmap.md) 中维护。

## 1. 用途、优先级与工作边界

所有前端任务开始前，先阅读根目录 [AGENTS.md](../AGENTS.md)、本文和 [ui-roadmap.md](ui-roadmap.md)，再核对 [架构与执行流程](architecture.md) 与当前代码。

- 当前代码是已实现行为的事实来源；进程边界、流式与历史展示、队列和模块职责见 [架构与执行流程](architecture.md)，数据格式见 [配置与持久化](configuration-and-storage.md)。
- 本文约束视觉和展示层实现；不改变架构、IPC 契约、业务数据结构或持久化格式。
- open-claude-ui 是设计参考，不是 NiCode 的上位规范。发生冲突时以用户当前指令、项目开发规则和已确认架构为准；无法兼容时先指出问题，停止扩大修改范围。
- 仅有路线图不代表获得一次实施全部任务的授权。每次只完成当前明确要求的一个小任务。
- 开始前记录已有差异；禁止覆盖、还原、格式化或顺手重构与本次任务无关的改动。

### 1.1 业务逻辑保护红线

**禁止 UI 改造破坏现有业务逻辑。** 普通视觉任务不得修改下列行为以迁就样式、组件或动画：

1. 后端、Runtime、主进程、preload、IPC 通道、请求参数、返回结构和事件订阅。
2. `session-state.ts` 中的事件身份、去重、排序、水位、历史合并、缓存、草稿和状态投影。
3. 路由与 Project / default / Session 身份、现有信息架构和设置分区。
4. 发送、继续、停止、排队、丢弃、重试、审批和设置保存的处理函数、时序与禁用条件。
5. 模型与 Provider 绑定、默认模型保存、可选推理等级和权限作用域。
6. 输入法、Enter / Shift+Enter、现有键盘导航、焦点恢复、关闭保护、滚动跟随和窗口控制行为。
7. Markdown 内容处理、HTML 转义、URL 处理、工具参数及结果原文。

允许优先修改 CSS；确需改 TSX 时，只增加必要的展示类或静态容器，保持回调、条件分支、稳定 key、组件身份和状态归属。容器变化仍须检查滚动祖先、焦点顺序、浮层裁切与可访问性，不能仅凭未改回调判断无行为影响。

若某项体验必须改变事件处理、业务状态或架构，另建独立任务说明原因、范围和验证方式；未经明确授权不得并入视觉任务。禁止用定时器、本地模拟状态或乐观成功提示替代真实业务结果。

### 1.2 现有技术与数据流

- 使用既有 React、Vite、普通 CSS 和 `@tabler/icons-react`。不因参考项目使用 Tailwind、Framer Motion 或 Lucide 就增加这些依赖。
- `main.tsx` 中的 Workspace 持有工作区状态与跨路由缓存，SessionRoute 定位会话，SessionPage 消费现有事件投影并展示消息。
- ComposerInput 只负责受控输入的 DOM 高度；ComposerModelPicker 展示选项并把选择交回页面，持久化由现有页面流程负责。
- `workspace.css` 是样式入口，导入 `conversation.css` 和 `settings.css`。先在入口收敛共用 Token，再由各区域消费。
- 不新增转发层、全局 UI 状态容器或通用组件框架。相同意图出现明确重复需求后，才考虑局部复用。

## 2. 设计方向与现状依据

方向：保留 NiCode 的中性工具界面，建立清楚的表面、文字、操作与状态层级。内容优先，交互克制，服务于持续阅读中文、代码和执行过程。

设计原则：

1. 对话与代码是主内容；导航、过程和辅助操作降低视觉权重。
2. 背景允许低对比，正文、操作和焦点必须清楚。
3. 同一组件角色使用同一字号、尺寸、圆角、间距和反馈。
4. 密度按内容分配；紧凑工具栏不应迫使正文或关键标签变小。
5. 所有反馈表达真实状态；没有数据时不虚构进度、耗时或执行阶段。
6. 一次改一个区域，每步均能验证并由负责人理解。

分析时 NiCode 已具备浅深主题、语义色、无边框助手正文、输入高度自适应、原生 popover、模型菜单键盘操作、弹窗焦点管理和减少动效支持，应继续复用。

主要优化点是：多处 9–11px 操作或说明文字、窄窗出现 8px 文字、主次按钮接近、圆角与尺寸分散，以及局部布局仅依赖窗口断点。当前侧栏已采用 4px 间距步进，不应推倒重做。

## 3. Token 使用约定

- 下表记录目标值；标为“保留”的值来自分析时的代码，标为“新增”的 Token 需要随对应任务落地。
- 沿用既有语义名称，不整体改名为 CDS 前缀，不复制参考项目的 35 阶灰度和橙色标尺。
- 组件应引用语义 Token，不重复写任意颜色、阴影、时长或尺寸。边界数据和光学校准可保留有说明的局部值。
- 相同意图共享 Token；不同意图不因数值暂时相同就强行绑定。
- 新增 Token 必须有当前使用场景；可选状态色尚无使用者时不提前写入代码。
- 浅深主题覆盖相同语义角色。保留当前主题选择与保存流程，不附带增加自动主题或密度设置。

| Token | 浅色 | 深色 | 用途 |

颜色核算依据：`#54544d` 配白字约 7.63:1；`#cecec6` 配 `#2c2c28` 约 8.86:1。参考示例的 `#d97757` 配白字约 3.12:1，不直接用于 NiCode 的小字号主按钮。新状态色也必须核对实际背景组合。

验收门槛：普通正文、标签、按钮和重要占位文字至少 4.5:1；用于辨认控件、选中和焦点的关键非文字标记至少 3:1。装饰性分隔线无需冒充控件识别边界。不得用整体降低 opacity 的方式让仍需阅读的内容失去可读性。

字重使用 400（正文）、500（操作）、600（标题）；原有品牌字标可保留当前强调。使用 rem 表达时以 16px 根字号换算，不复制 CDS 的 16/17 光学缩放因子。

- 不引入专有字体，不为普通系统字体设置未经验证的可变字体轴或暗色字重补偿。
- 不通过把关键文字缩至 8–10px 来适配窄窗。中文说明应允许自然换行。
- 数量、计时、行号等已有动态数字使用 `font-variant-numeric: tabular-nums`；不为样式增加新的计时或计量逻辑。
- 正文和错误信息使用 `overflow-wrap: anywhere` 处理超长连续串；普通文本保持 `word-break: normal`。
- 代码保留缩进，使用独立横向滚动；不得对代码全局使用强制折行。
- 正文优先自然排版；流式区域避免反复均衡全文换行。静态标题可在验证稳定后使用 `text-wrap: balance`。

### 3.6 阴影、边界和高程

| Token / 角色 | 浅色目标 | 深色目标 |
| --- | --- | --- |
| 普通列表与内容分组 | `none` | `none` |
| `--shadow-small`，Composer 轻高程 | `0 2px 8px #0000000a` | `0 2px 10px #00000026` |
| `--shadow-popover`，新增 | `0 8px 24px #0000001f, 0 1px 3px #0000000d` | `inset 0 0 0 1px #ffffff14, 0 10px 28px #00000066` |
| `--shadow`，模态高程 | `0 16px 48px #00000026` | `0 16px 48px #00000080` |

- 阴影表达浮层与画布关系，不为每张卡片增加悬浮感。
- 默认使用 1px 弱边界；装饰性发丝线只在目标显示缩放下验证后局部使用，不全局强制 0.5px。
- Composer、弹窗等密集容器以一个主要外轮廓组织内容；内部按钮主要采用填充或 Ghost，分组用留白和单向细线。
- 字段可保留独立边界；不能为了单边框规则去掉控件辨识和焦点提示。
- 聚焦与选中通常减少内凹按压效果；Composer 按负责人确认保留原有聚焦阴影。`--shadow-focus`、`--shadow-pressed` 的其他既有使用随对应区域核对，不提前删除仍有消费者的变量。
- 焦点反馈避免使用线条把控件框起来，采用可辨识的背景或柔和阴影，并保持键盘焦点可见。Composer 保留原有 `focus-within` 背景和阴影，不为输入区增加轮廓线；其它既有焦点样式在各自任务中逐步核对，不因本规则顺带改动业务区域。
- 原有层叠次序不是本轮重构目标。原生 popover 保持顶层特性；新增 stacking context 前核对菜单、审批、模态和窗口按钮的关系。

## 4. 组件与交互规范

### 4.1 通用状态

组件按实际语义覆盖 default、hover、focus-visible、active、disabled、loading、error、selected 等适用状态。状态由现有属性或业务数据决定；不要求每个组件生成所有变体。

- 主操作：中性 `--accent` 填充，`--on-accent` 前景；用于发送和当前流程的最终保存、创建确认等。
- 次操作：低对比填充、普通前景；用于取消、次级确认等。
- Ghost：透明背景，悬停时轻填充；用于图标、列表内操作和辅助工具。
- 危险操作：错误色与明确文案；不把普通停止一律当成删除。
- 主要动作按上下文识别；列表里的每个新增、编辑都不必变成实色按钮。
- 请求中保留原有禁用与防重复行为；反馈占位尽量稳定，避免按钮宽度跳动。
- 隐藏的辅助操作在 focus-within 和粗指针环境下可见；不得使键盘用户聚焦到不可辨识操作。

### 4.2 工作区与侧栏

保留项目、项目内对话、独立对话、设置和主题入口，不按参考项目重组为执行环境分类。

- 延续 36px 侧栏行、4px 步进和现有文字缩进；宽度沿用现有窗口断点，除非当前任务明确调整。
- 选中项使用轻填充和适当字重；悬停比选中弱，焦点另有可见反馈。
- 长名称单行截断，保留当前完整名称提示；分组计数和折叠箭头不挤压主文字。
- 保留现有展开、导航与收起逻辑；不为了动效更换组件 key、卸载策略或新增自动折叠状态。
- Windows 自绘窗口按钮、拖拽区域和关闭仅最小化的既有约定保持不变。

### 4.3 Composer 与模型菜单

- 首页与会话页共用相同的输入外壳、12px 圆角、14/22px 正文、32px 操作尺寸。
- 输入区和底部工具栏构成一个实体，内部文本域透明；常态、悬停、聚焦层级依次增强。
- 首页和会话使用圆形发送入口；会话运行时草稿为空（包括只有空白）则同一入口显示停止，草稿有内容则显示加入队列。停止中显示禁用的停止状态；继续沿用现有发送、排队和停止流程及忙碌保护，Enter 仍只发送。
- ComposerInput 的单行起步、增长、上限后内部滚动和清空收缩由现有实现负责；样式不得同时引入另一套高度控制。
- 保持 Enter / Shift+Enter 和输入法处理。额外的 keyCode 229 保护属于事件任务，不得顺带加入。
- ComposerModelPicker 保留现有顶层原生 popover、定位、外部关闭、方向键、Home / End、Escape 和焦点恢复。
- 模型名称使用 13px 界面字号，推理等级等辅助信息使用 12px；长名可截断，菜单内允许完整内容换行。
- 模型和等级继续由 Provider 配置驱动，不固定为五档，不新增预设模型、推理开关、用量表或推断推荐项。

### 4.4 对话、执行过程与代码

- 助手正文透明、无闭合外框；用户消息使用中性轻填充，最大宽度延续约 85%–86% 的当前比例。
- 对话正文采用 14/24px；消息之间以 24px 为常用基准，组内以 8–12px 组织。
- 保留当前聊天外层最大宽度 820px、首页 720px 的基础角色；聊天现有宽屏 40px 边距可继续使用，窄窗按内容区调整。
- 执行过程、思考与工具入口统一箭头、图标、计数和 12px 辅助文字；原文详情使用 13/20px 等宽排版。
- 保留原生 details 的展开状态与完成态父折叠，不为动画替换状态模型，不重写 final answer 识别或事件投影。
- Markdown 标题、段落、列表、引用、表格与代码有稳定纵向节奏；段落间距约 0.85em，标题与前后内容形成清楚层级。
- 代码块 12px 圆角、16px 左右内容内距、主题适配底色；长代码独立横向滚动。工具结果保留当前原文展示。
- 表格在自身区域横向滚动；不能撑宽页面或让字段名称逐字竖排。
- 保留消息复制的既有原文、异常反馈和持续时间；新增代码复制、语法高亮或 Diff 交互另列任务。

### 4.5 审批、队列和错误

- 审批继续在 Composer 上方出现，保留当前非模态语义；不能改成强制模态并接管整个焦点流。
- 清楚展示工具名、原因、完整参数和仅本次调用的范围。正文滚动、底部批准与拒绝操作保持可见。
- 批准与拒绝均可辨识；提交中显示既有反馈，结果由真实审批事件决定。不增加始终允许或本地模拟成功。
- 排队、准备中、未发送、失败使用不同文字和适度填充；不把队列展示升级为离线持久化承诺。
- 错误采用现有错误信息与重试入口；不新增自动重试、不删除详细原因、不用动画掩盖失败。
- 停止中与运行中沿用现有 phase；颜色与动效不得让停止中看起来已停止。

### 4.6 设置、表单、弹窗与搜索

- 保留模型、MCP、技能分区和现有供应商列表—详情结构。
- 标签 13px、字段 40px、说明 12/18px；同类字段、按钮、空态与错误保持一致。
- 表单独立区域通过留白组织；分区间距 24–32px，不为每一行增加一层卡片。
- Provider / Model 参数、API Key 留空语义、MCP 保存与连接状态、Skill 作用域和启停均保持原逻辑。
- 模态采用 16px 圆角、清楚标题和受限高度；内容可滚动，主操作在边界尺寸下可达。
- 复用 useDialogFocus、已有 Escape 分层关闭、忙碌时关闭保护与焦点恢复，不复制参考弹窗的事件实现。
- 搜索保留现有结果、选择与键盘逻辑；结果名称与来源分层，当前项和焦点项清楚。
- 原生 select / picker 只统一外观，保留选择和键盘行为。
- 新对话和已有会话的权限选项间留出间距，避免选中与悬停背景相接；分别保留现有按钮菜单与原生 select 的选择行为。新对话权限入口和菜单项使用背景表达键盘焦点，不加轮廓线。
- 空态继续展示现有真实内容与可用入口；不新增未经实现的承诺。

## 5. 动效规范

使用既有 CSS 能力；不为微动效引入动画依赖。

| Token | 目标值 | 用途 |
| --- | --- | --- |
| `--duration-press` | `60ms` | 按压反馈 |
| `--duration-fast` | `120ms` | hover、图标和箭头 |
| `--duration-base` | `200ms` | 菜单、弹窗与局部显隐 |
| `--duration-panel` | `280ms` | 已有较大展示区域的过渡 |
| `--ease-out` | `cubic-bezier(.165, .84, .44, 1)` | 常规反馈与进入 |
| `--ease-snap` | `cubic-bezier(.32, .72, 0, 1)` | 快速对齐 |

- 显式声明过渡属性，不使用 transition: all。
- hover 主要改变前景、背景和必要阴影；导航行、字段、代码块保持位置稳定。
- 菜单、审批浮层入场可使用 4–6px 位移与透明度，约 120–200ms。关闭不得因等待动画而延迟现有业务处理。
- 按钮按压可用 scale(0.98)，不采用全局强弹簧、1.32 倍过冲或每次点击的装饰性跳动。
- 流式正文即时显示，不逐 token 或逐字符模糊，不在每次事件更新时重播整块入场动画。
- 工作指示可采用约 1.4–2s 的低幅透明度周期；同一区域只保留一个主要循环提示，并有静态状态文字。
- 骨架屏仅在当前加载分支已有明确范围时采用；不伪装未知结构，不为展示增加新的加载状态机。
- 不把 CSS 动画等同于自动零重排或固定帧率；transform / opacity 优先，布局属性动画需实际检查。
- 保留全局 prefers-reduced-motion 降级；动画关闭后状态仍完整。显式 smooth 滚动的实现若需改变，另列事件任务。
- details 高度动画仅在保留原生语义、展开状态和键盘行为且目标环境验证后使用；不满足时保留即时展开。

## 6. 响应式、缩放与可访问性

窗口媒体查询负责外壳；容器查询负责局部内容密度。不能仅因窗口较宽就假定设置详情、浮层或工具栏有足够宽度。

| 组件内容区宽度 | 目标布局 |
| --- | --- |
| ≥576px | 完整工具栏与辅助提示 |
| 480–575px | 收紧间距，优先省略快捷键等非关键提示 |
| 384–479px | 模型名称限宽，关键控件允许两行 |
| <384px | 明确两行布局，权限、模型、停止、发送仍可达 |

- 上述断点是 NiCode 局部适配起点，不代表新增移动端产品或改变 BrowserWindow 最小尺寸。
- 保留现有侧栏开关和窄窗浮层方式；不自动增加抽屉、遮罩、折叠状态或滚动锁。
- 不隐藏唯一业务入口来消除溢出；不将关键文字缩成 8–10px。
- 设置表单按详情容器实际宽度切换单列与双列；列表、导航和字段顺序保持可理解。
- flex / grid 子项正确使用 min-width: 0；代码、表格、长参数有自己的滚动或换行边界。
- 原生 popover 不退回易被 overflow 祖先裁切的绝对定位菜单。
- 优先保持 DOM 阅读顺序与键盘顺序一致；不要仅用 CSS 重新排列成不一致的操作顺序。
- 粗指针操作区至少按 44px 目标检查，焦点可见；扩展命中区不得重叠或误触相邻操作。
- 检查 100%、125%、150% 缩放，必要时检查 200%；不假定参考项目的 macOS 字体和显示比例适用于 Windows。
- 使用浏览器能力检测保留可用布局，新的 container、mask 等效果不可成为内容可读性的唯一前提。
- 滚动渐隐只在对应容器确有遮罩需求时单独评估；当前默认不加。若未来采用，触顶和触底内容必须完整，不改变滚动监听和图钉逻辑。
